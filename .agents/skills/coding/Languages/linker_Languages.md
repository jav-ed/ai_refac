# Languages

Language guides refine naming and syntax and hold what we know about working in one language, such as how to test it. They never override the mandatory universal rules in [SKILL.md](../SKILL.md): read those first, then only the guide for the language you are writing or reviewing.

- [JS / TS naming](Js_Ts/js_Ts.md): the standard community naming for JS and TS (variables, functions, classes, constants, files, components). Use it when the repository already follows this style or the operator chose the standard option.
- [JS / TS testing](Js_Ts/testing.md): choosing Bun or Vitest, one file suffix per runner, grouping tests by cost, time budgets, real-database tests, and which tests are not worth writing. Read it before creating or running a JS/TS test, together with the [Testing](../Tooling/Testing/testing.md) rules.
- [Markdown and non-code files](markdown.md): the naming rule for documentation and other non-code files (lowercase first letter for files, uppercase for folders).
- [Improved_Camel_Snake convention](improved_Version.md): the alternative naming style for code, files, and folders in every language, with examples. Use it when the repository already uses it or the operator selects it.
