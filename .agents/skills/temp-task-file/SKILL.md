# Temp task file

A new message while you work is by default a new task, not a new direction. Add it to your file, say in one line that it is noted, and go back to what you were doing. You work through the list; you do not react message by message.

The benefits are inshallah: you see the list of tasks and can decide the order, you get a nice overview, you don't skip tasks, and each task gets the time and effort it needs.

- Create `Scratch/Agent_Tasks/<topic>_<unique-id>.md` when the user asks, or when a second task arrives while you work. Never take over another agent's file unless the user explicitly asks. Continue using your own file when resuming your work.
- One line per task, in the user's words. It is a to-do list only: no protocol, no history, no investigation notes. Remove done tasks.
- Two headings: "Asked" (from the user: do these) and "Noticed" (found by you: do not start without being asked).
- Re-read the file when you finish a task and before you end your turn. New tasks may have arrived.
- Order: the user's order wins; otherwise quick or blocking tasks first.
- Handle a message differently only when it contradicts the current work or changes its order: reach a safe point, say in one line what changed, update the file, and follow the newest instruction. If two instructions clash and you cannot tell which wins, ask.
