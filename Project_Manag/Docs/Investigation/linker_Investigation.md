# Investigation

In-depth studies that decided how a feature is built, kept here because Scratch is disposable and the reasoning must outlive it. Each document records what was tried, on which cases, with which numbers, and which failure modes surfaced. Open one before changing the engine it covers or before adding the same capability for another language.

## Docs

- [TypeScript rename engines](typescript_Rename_Engines.md): which tools can rename a TypeScript symbol (TypeScript 7 native, TypeScript 6 LanguageService, typescript-language-server, Biome, oxlint, Oxc, ts-morph), how each did on 16 cases, speed and memory on a 2,100-file project, and the silent failures found: undetected name clashes and shadowing, and `baseUrl` making the TypeScript 7 engine miss files without an error.
- [Astro options](astro_Options.md): whether `refac` can move files and rename symbols in Astro projects (`.astro`, `.mdx`, assets, CSS). What 0.1.4 does today on eight cases (four report success and leave the build broken), the Astro language server against TypeScript 7.1 with `@astrojs/ts-content-mapper` (edits applied to copies, checked with `tsc` and `astro build`, timed on a real 290-component site), the gaps no engine covers (MDX, asset and CSS references), the `baseUrl` removal in TypeScript 7, and the decided direction: moves through the Oxc engine, renames through the 7.1 server.
- [Kotlin options](kotlin_Options.md): which tools could give Kotlin file and package moves and symbol rename for Android work (JetBrains Kotlin language server, fwcd server, OpenRewrite, IDE plugins, Analysis API), why the official server was chosen, and the hands-on results against build 263.6379.0: startup and readiness signals, the one-target-directory limit of file moves, stale watcher state that looks like success, unrenamed Java package lines, accepted shadowing renames, and the Android XML and `R` gaps. Also the 2026-10-31 evaluation of kmp-lsp (Rust, tree-sitter, no JVM, no expiry): seven rename cases against the JetBrains baseline, why it cannot move files and renames unsafely, and when to look again.
- [Markdown options](markdown_Options.md): which existing tools move Markdown files and fix links (docmv, markmv, mdref, the VS Code Markdown language service, Marksman, markdown-oxide), the 13-shape corpus all three runnable tools were tested on, what each missed or damaged (HTML references, multi-line definitions, folder links, `%20` paths, moved folders, an emptied image destination), and why the embedded `pulldown-cmark` engine stays. Also lists what to borrow: dry run, heading rename with `github-slugger`, an `explain` report.
- [Symbol rename options](symbol_Rename_Options.md): which language server renames a symbol in Go (gopls), Rust (rust-analyzer), Python, and Dart, and why. The Python matrix compares basedpyright, pyright, Pyrefly, ty, and Rope on nine renames and five name clashes (Pyrefly and ty miss five cross-file cases each, nobody refuses a clash, only basedpyright can list overrides), plus the gopls partial answers under load, rust-analyzer's silence about `macro_rules!` bodies, the Dart server answering from files it has not analysed yet, and the measured cost of one rename per language.
