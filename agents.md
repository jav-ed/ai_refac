Project_Manag/Docs/doc_Start.md can be used to get a quick understanding of this project inshallah

Before you build, add a test file or start a new background tool, read Project_Manag/Docs/Setup/resource_Use.md: the Cargo profile keeps debug information out of the build (a full one once wrote 19 GB and filled the sandbox disk), integration tests are grouped as tests/<group>/main.rs and a new .rs file directly in tests/ is not allowed, and every tool you start must be stopped again and have its memory measured.

**Kotlin tests: do not call them like crazy.** A Kotlin test starts a language server (20 to 32 seconds, about 2 GB) and the whole group takes about 7 minutes, so running them after every edit destroys your efficiency. Invoke them only when the change you made actually needs them. By default only the quick set runs, within 30 seconds: `cargo test --test kotlin quick:: -- --ignored --test-threads=1`. Every other Kotlin test is blocked and fails at once with that message unless the command says `REFAC_KOTLIN_TESTS=all`; do that only for the few tests that cover your change, in ONE command with `--test-threads=1` (the tests share one server per fixture inside it), and run the whole group once before a push at most, never repeatedly. Project_Manag/Docs/Setup/kotlin_Server.md lists which tests cover which change. The `refac` tool itself also refuses a single Kotlin move or rename and explains why (`refac guide kotlin`): collect the changes and make them in one call.
